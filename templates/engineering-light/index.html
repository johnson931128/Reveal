OVERVIEW

四種主要的 EtherCAT addressing family

說明

EtherCAT datagram 的存取方式可從位址語意分成四類：Auto Increment、Configured Address、Broadcast、Logical Address。
前 3 類主要圍繞 slave 與 local register / local memory 的存取；Logical Address 則進一步透過 FMMU 映射到 process data 的邏輯位址空間。

Auto Increment

逐站探索與拓樸查找

Configured Address

已識別 slave 的定向存取

Broadcast

對所有 slave 執行共同操作

Logical Address

對 process data 進行週期性邏輯存取

結論

前 3 類偏向裝置導向，Logical Address 偏向資料路徑導向。

01 / DEVICE / POSITION

Auto Increment

指令APRD / APWR / APRW
地址欄位ADP + ADO

核心機制

Master 送出帶有 Auto Increment 語意的 datagram。封包沿線經過各 slave 時，ADP 會依序變化。當某個 slave 視角下看到 ADP = 0 時，該 slave 會執行這次存取。

補充說明

這種模式的重點不是把 ADP 當成固定站址，而是利用封包逐站傳遞時的遞增特性，讓操作自然落在某一個位置的 slave。

封包觀察

啟動階段常看到 0x0000、0xFFFF 這類起始值。分析時要觀察的是：

  • ADP 如何隨封包傳遞而變化
  • 哪個 slave 在看到 ADP = 0 時實際執行操作
  • 搭配的 ADO 指向哪個 local register / local memory 區域

典型用途

  • 拓樸查找
  • 逐站探索
  • 初始化早期的 slave discovery
  • 讀取基本識別資訊後再配置站址

結論

Auto Increment 是從「鏈路順序」出發的存取方式。

02 / DEVICE / NODE

Configured Address

指令FPRD / FPWR / FPRW
地址欄位Station Address (ADP) + ADO

核心機制

當 slave 已經具有 configured address 後，Master 可直接指定目標站址，對單一 slave 進行定向讀寫，不再依賴 Auto Increment 的逐站命中方式。

補充說明

這時 ADP 應理解為 configured station address。若系統有啟用 alias，則可由 alias 對應到 station identity 的匹配邏輯。

封包觀察

分析時要關注：

  • ADP 是否已成為穩定的 configured station address
  • ADO 對應的 local register 是什麼
  • 操作是否已從 discovery 階段轉入穩定單站操作

典型用途

  • 對特定 slave 讀寫 ESC register
  • slave 身分確立後的定向控制
  • 後續個別參數與狀態存取

結論

Configured Address 是從「已知目標 slave」出發的存取方式。

03 / DEVICE / ALL

Broadcast

指令BRD / BWR / BRW
地址欄位All Slaves + ADO

核心機制

Broadcast 不是鎖定單一 slave，而是讓所有 slave 對同一個 local offset 進行共同存取。

補充說明

這種模式的重點不在於辨識「哪一站被命中」，而在於「所有 slave 是否都對同一個 ADO 做了相同操作」。

封包觀察

分析時要關注：

  • 使用的 ADO 是哪個共通欄位
  • 所有 slave 是否都對該 local offset 參與存取
  • 封包行為是否符合初始化或共通狀態操作

典型用途

  • 初始化階段共通設定
  • 全體共同狀態讀寫
  • 對所有 slave 的一致性操作

結論

Broadcast 是從「全體 slave」出發的存取方式。

04 / LOGICAL / FMMU

Logical Address

指令LRD / LWR / LRW
地址欄位32-bit Logical Address

核心機制

Master 存取的是 logical address，而不是直接指定某個 slave 的 ADP / ADO。邏輯位址範圍會經由 FMMU 映射到對應 slave 的 local memory，進而形成 process data 的資料路徑。

補充說明

這個 family 的重點已從「命中哪個 slave」，轉成「logical region 如何被映射到實際資料區塊」。

封包觀察

分析時要關注：

  • logical address 範圍
  • 對應 FMMU 映射結果
  • 最終落到哪些 slave / local memory 區段
  • 是否為 PDO / cyclic process data path

典型用途

  • PDO / process data 週期性讀寫
  • 邏輯位址空間的 cyclic access
  • 與 FMMU / SyncManager 分析串接

結論

Logical Address 是從「資料路徑與映射結果」出發的存取方式。

01

STATION ADDRESS

0x0010 Configured Station Address

透過 APWR 寫入 Configured Station Address，並將該值綁定到由 Auto Increment Address 推導出的 topology position。

APWR ADO = 0x0010 ↓ Configured Station Address
02

AL STATE

0x0120 AL Control

擷取 Master 寫入的 AL Control 值，後續整理為 Slave 的 Control waveform。

0x0120AL ControlMaster requested state
0x0130 AL Status

擷取 Slave 回報的 AL Status 值，後續整理為 Slave 的 Status waveform。

0x0130AL StatusSlave current state
03

SII EEPROM IDENTITY

0x0502 EEPROM Control / Status

透過 APWR 發出 EEPROM Read 操作，並取得本次欲讀取的 EEPROM Word Address。

APWR ADO = 0x0502 ↓ EEPROM Read Command + EEPROM Word Address
0x0508 EEPROM Data

接續前一筆 EEPROM Read，透過 APRD 取得 EEPROM Data，再依先前記錄的 EEPROM Word Address 判斷資料用途。

APRD ADO = 0x0508 ↓ EEPROM Data
EEPROM Word 0x0008Vendor ID
EEPROM Word 0x000AProduct Code
